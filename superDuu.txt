5. Khi nào nên xóa __pycache__?
Bạn có thể xóa khi:

Gặp lỗi kỳ lạ, nghi ngờ do cache cũ (ví dụ sửa code nhưng chạy vẫn như cũ).

Đổi phiên bản Python và muốn đảm bảo không dùng bytecode cũ.

Dọn dẹp trước khi đóng gói, deploy.

Xóa an toàn:

bash
# Trong thư mục dự án
find . -type d -name __pycache__ -exec rm -rf {} +
# hoặc
find . -name "*.pyc" -delete
Python sẽ tự tạo lại __pycache__ khi cần.

6. __pycache__ trong các tình huống cụ thể
a) Chạy script bình thường
bash
python3 main.py
Python tạo __pycache__ trong cùng thư mục với main.py và các module được import.

b) Chạy module bằng -m
bash
python3 -m package.module
__pycache__ sẽ xuất hiện trong các thư mục có file .py được import.

c) Dùng virtualenv / venv
__pycache__ vẫn được tạo trong thư mục code của bạn, không phải trong venv.

venv thường đã được thêm vào .gitignore riêng.

d) Deploy lên server / Docker
Bạn có thể:

Không gửi __pycache__ (server tự tạo lại).

Hoặc tạo trước trên môi trường build để tăng tốc khởi động.

Trong Docker, nhiều người vẫn bỏ qua __pycache__ vì:

Image thường được build từ source sạch.

Container thường chạy ít lần, lợi ích cache không lớn so với việc giữ image gọn.
